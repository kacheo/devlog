# devlog — Engineer CLI Journal: High-Level Design

**Date:** 2026-06-01  
**Status:** Draft  
**Language:** Go  
**License:** Apache 2.0

---

## Overview

`devlog` is a local-first CLI tool that lets engineers keep a structured daily work journal. It auto-imports git commits and PR activity from configured repositories, exposes date-range views and machine-readable output so AI agents (Claude Code, scripts) can read and write entries programmatically.

The core philosophy: **plain markdown files you can always open in your editor**, with just enough structure that tooling can extract signal from them.

---

## Goals

- Zero-friction daily logging: `devlog add "Fixed the auth bug"` is the whole workflow
- Automatic git activity capture without manual bookkeeping
- Date-range views: `devlog show --from yesterday` produces a multi-day summary
- Agent-friendly: every output command supports `--json` with a stable schema
- No network dependency for core use (GitHub access is optional and graceful)

## Non-Goals

- Remote sync or multi-machine support
- LLM-based summarization (no API calls)
- TUI or interactive interface
- MCP server (CLI subcommands + `--json` are sufficient for agent use)
- Windows support in v1 — the binary builds cross-platform, but the `post-commit` hook and
  `$EDITOR` handling assume a POSIX shell, so only macOS and Linux are tested and released

## Commands

```
devlog init [--non-interactive]               # first-time setup wizard (prompts; --non-interactive uses defaults/flags only)
devlog add "text" [--section SECTION] [--tag TAG ...]  # append bullet to today's file; --tag adds frontmatter tags
devlog edit [DATE]                            # open DATE (default: today) in $EDITOR
devlog show [today|yesterday|YYYY-MM-DD|week] # print entries (week = last 7 days)
devlog show --from DATE [--until DATE]        # print entries for a date range (--until defaults to today)
devlog sync [--quiet]                         # import today's commits + PRs
devlog search QUERY                           # full-text search across all journal entries
devlog rm SECTION INDEX                       # remove a bullet by 1-based index
devlog update SECTION INDEX "new text"        # replace a bullet by 1-based index
devlog workspace [add|list|exclude]           # manage workspace directories
```

**Global flags:**
- `--json` — emit structured JSON instead of human-readable output. Applies to the output
  commands (`show`, `sync`). It is ignored by `edit` (which only opens an editor)
  and `init`.
- `--date YYYY-MM-DD` — target a specific date instead of today. Applies to `add`, `edit`,
  `show`, `sync`. If a command also takes a positional date (e.g. `show yesterday`,
  `edit 2026-05-30`), **the positional argument and `--date` are mutually exclusive** — passing
  both is an error rather than a silent winner.

All dates are interpreted in the machine's **local time zone** (see Time Zones below).

## Daily File Format

Each day is stored as `$DEVLOG_DIR/YYYY-MM-DD.md`. New files are scaffolded with all sections present (empty bodies are fine).

```markdown
---
date: 2026-06-01
tags: [auth, backend]
commits:
  - { sha: abc1234, message: "fix: oauth token refresh loop", repo: api-server }
  - { sha: def5678, message: "feat: add rate limiter to /v2/users", repo: api-server }
prs:
  - { number: 142, title: "Add rate limiter to user endpoints", state: merged, repo: api-server }
---

## Notes
- Fixed the OAuth token refresh loop
- Reviewed Alice's PR on the API rate limiter

## Commits
- abc1234 fix: oauth token refresh loop (api-server)
- def5678 feat: add rate limiter to /v2/users (api-server)

## PRs
- #142 Add rate limiter to user endpoints [merged] (api-server)

## Blockers
- Waiting on DevOps to provision staging DB
```

### Source of truth

Day files have two kinds of sections, with different ownership:

- **Machine-imported, tool-owned: `commits` and `prs`.** The structured lists in
  frontmatter are the **source of truth**. The `## Commits` and `## PRs` body sections are a
  human-readable *rendering* of that frontmatter, regenerated by `devlog sync`. No command
  ever recovers structured fields by parsing the rendered bullet (`- <sha> <subject> (<repo>)`) —
  that string is lossy (commit subjects can contain `(`, `[`, etc.) and is display-only.
  This is what lets `show --json` emit identical, reliable objects regardless of how the file was rendered.
- **Human/agent-authored: `## Notes` and `## Blockers`.** Free prose. The tool only appends
  here, never rewrites.

**Section rules:**
- `devlog add` appends a `- ` bullet to `## Notes` by default; `--section blockers` targets
  `## Blockers`, etc. (see section-name matching below).
- `devlog sync` writes the `commits`/`prs` frontmatter lists and re-renders the matching body
  sections. It deduplicates by commit SHA and PR number, so running it multiple times is
  idempotent.
- Sections are always present in new files. Users may freely edit `## Notes`/`## Blockers`;
  edits to `## Commits`/`## PRs` body are overwritten on the next `sync` (edit `commits`/`prs`
  in frontmatter instead).
- **Section-name matching:** `--section` values are case-insensitive and singular/plural is
  normalized to the canonical heading — `note`/`notes` → `## Notes`, `blocker`/`blockers` →
  `## Blockers`. An unknown section name is an error listing the valid sections (`devlog` does
  not silently create arbitrary sections via `add`).
- The tool parses body sections by matching `## SectionName` headings. Any heading not in the
  known set is preserved verbatim and ignored.

## Configuration

File: `~/.config/devlog/config.toml`  
Created by `devlog init`. Hand-editable at any time.

```toml
[journal]
dir    = "~/devlog"    # where day files are stored
editor = ""            # falls back to $EDITOR, then $VISUAL, then vi

[github]
token = ""             # optional; if empty, devlog falls back to `gh` CLI auth

[[repos]]
path = "~/workspace/api-server"
name = "api-server"
# github_slug = "acme/api-server"   # optional; override the owner/repo derived from `origin`

[[repos]]
path = "~/workspace/frontend"
name = "frontend"
```

**Environment variable overrides** (useful for agent/CI contexts):
- `DEVLOG_DIR` — overrides `journal.dir`
- `DEVLOG_EDITOR` — overrides `journal.editor`
- `DEVLOG_GITHUB_TOKEN` — overrides `github.token`

`devlog init --add-repo ~/workspace/new-service` appends a repo entry without rewriting the rest of the config.

`devlog init --non-interactive` writes a default config (and skips the git-hook prompt) without
any TTY interaction, so agents and CI can bootstrap `devlog` unattended. Repos can be supplied
with repeated `--add-repo` flags, and any value can be overridden via the `DEVLOG_*` environment
variables above.

## Git Integration

### Commit Import

For each configured repo, `devlog sync` runs a `git log` over the **target day** (today by
default, or the day given by `--date`), in local time:

```
git log --since="<target-day> 00:00:00" \
        --until="<target-day> 23:59:59" \
        --author="$(git -C <repo.path> config user.email)" \
        --pretty=format:"%h %s"
```

Each returned commit is stored as a structured entry (`{sha, message, repo}`) in the day file's
`commits` frontmatter and rendered as `- <sha> <subject> (<repo-name>)` under `## Commits`.
Commits already present (matched by SHA prefix) are skipped.

### GitHub repo identity

PR import needs an `owner/repo` for each configured repo. `devlog` derives it from
`git -C <repo.path> remote get-url origin`, parsing both SSH (`git@github.com:owner/repo.git`)
and HTTPS (`https://github.com/owner/repo.git`) forms. If `origin` is missing or is not a
GitHub remote, PR import is skipped for that repo (commits still import). A repo's
`owner/repo` may be overridden in config via an optional `github_slug = "owner/repo"` field
under its `[[repos]]` entry, for non-`origin` or non-standard setups.

### PR Import

Two modes, tried in order:

1. **`gh` CLI** (preferred): `gh pr list --repo <owner/repo> --author=@me --state=all
   --json number,title,state,updatedAt`, then filtered client-side to PRs whose `updatedAt`
   falls on the target day. (`updatedAt` must be in the `--json` field list so the date filter
   has data to work on.) Requires `gh auth login` but no extra config.
2. **GitHub REST API**: Used when `github.token` is set and `gh` is not available. Calls
   `/repos/:owner/:repo/pulls?state=all` (with `:owner/:repo` from the same remote parsing),
   filters by author and `updated_at` on the target day.
3. **No GitHub access** (no `gh`, no token, or no GitHub remote): PR section stays empty;
   commits still import. No error, no noise.

PRs are stored as structured entries (`{number, title, state, repo}`) in the `prs` frontmatter
and rendered under `## PRs`. Deduplicated by PR number per repo.

### Auto-wiring

`devlog init` offers to install a `post-commit` git hook in each watched repo:

```sh
#!/bin/sh
# >>> devlog managed block >>>
devlog sync --quiet
# <<< devlog managed block <<<
```

With this in place, every commit automatically updates the journal. `--quiet` suppresses all output so it doesn't interrupt the commit flow.

**Existing hooks:** if a `post-commit` hook already exists, `devlog` does not overwrite it. It
appends its managed block (delimited by the markers above) to the existing hook, and on a later
re-install it replaces only the content between those markers. If the file isn't writable or
isn't a shell script it can safely append to, it warns and skips rather than failing.

**Concurrency & write safety:** a rebase, a squash-merge, or two watched repos committing at
once can fire several `devlog sync` processes that write the **same day file**. To prevent
corruption, all day-file writes (`add` and `sync`) take a per-file advisory lock and write
atomically (write to a temp file, then `rename`). A `sync` that loses the lock race waits
briefly and retries; it never partially writes.

## Show Output (`--json`)

`devlog show today --json` returns a single day entry (or an array for `week` and range views):

```json
{
  "version": "1",
  "date": "2026-06-01",
  "tags": ["auth", "backend"],
  "sections": {
    "notes":    ["Fixed the OAuth token refresh loop", "Reviewed Alice's PR"],
    "commits":  [
      { "sha": "abc1234", "message": "fix: oauth token refresh loop", "repo": "api-server" }
    ],
    "prs":      [
      { "number": 142, "title": "Add rate limiter to user endpoints", "state": "merged", "repo": "api-server" }
    ],
    "blockers": ["Waiting on DevOps to provision staging DB"]
  }
}
```

`notes` and `blockers` are arrays of strings (free prose); `commits` and `prs` are arrays of
structured objects. A consumer never has to parse a rendered bullet to get a commit SHA or PR
number.

For `devlog show week --json` and `devlog show --from DATE --json`, the top-level value is an
array of these objects, one per day that has a file. Requesting a single date with no file
returns `null` (and exit code 0); range views simply omit days with no file.

---

## Time Zones

`devlog` is a tool about *your work day*, so all day boundaries are **local time**: the file
name `YYYY-MM-DD`, the frontmatter `date`, the `--date`/positional date arguments, "today" /
"yesterday", and the `--from`/`--until` window are all computed in the machine's local zone. The
git import (`git log --since`) uses local time to match.

## Agent Usage

`devlog` is designed so CLI-based agents (Claude Code, shell scripts) can use it with no special integration:

```bash
# Agent logs what it did after completing work
devlog add "Refactored auth middleware to use short-lived tokens"

# Agent reads today's entries to understand context
devlog show today --json | jq '.sections.notes'

# Agent reviews recent activity across multiple days
devlog show --from yesterday --json
```

No MCP server is needed. The `--json` contract (versioned, stable) is the integration surface.

## Error Handling

- Missing journal dir → friendly message suggesting `devlog init`
- Missing `gh` and no token → sync skips PR import silently
- Repo path not found → skipped with a warning, not a fatal error
- Malformed day file → sections parsed defensively; unrecognized content is preserved verbatim
